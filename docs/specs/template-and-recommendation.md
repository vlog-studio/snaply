# 스펙 — 템플릿, 스냅 추천, 스냅 내용 분석

**작성일**: 2026-09-02
**상태**: 현행 — 템플릿·추천·분석 요구사항의 원천

## 템플릿

- **TPL-1** `구현됨` — 템플릿은 무비의 **형태**다: 촬영 지시 슬롯 목록(레이블·힌트)과
  스타일·BGM. 슬롯의 레이블은 사람에게 주는 촬영 지시이지, 채워진 스냅의 내용에 대한
  주장이 아니다.
- **TPL-2** `구현됨` — 템플릿 카탈로그는 **서버가 소유**한다. 앱은 카탈로그를 캐시하고,
  서버가 죽어도 내장 폴백으로 템플릿 화면이 동작한다. 앱이 모르는 스타일의 템플릿은
  앱이 건너뛴다.
- **TPL-3** `구현됨` — 템플릿으로 시작하면 앱이 라이브러리에서 **한 번의 외출**을 찾아 슬롯을
  즉시 채운다(로컬 매칭 — 촬영 시각·좌표만 사용). 빈 슬롯은 `지금 찍기`로 바로 촬영해
  채울 수 있고, 결과는 일반 무비 초안이 되어 자유 편집을 거친다.

## 스냅 자동 추천 (서버)

- **REC-1** `구현됨` — 서버 추천은 스냅 내용 분석을 근거로 각 슬롯에 넣을 스냅을 제안한다.
  **앱은 추천을 기다리지 않는다** — 로컬 매칭이 먼저 화면을 채우고, 추천은 **사용자가
  손대지 않은 슬롯에만** 얹힌다. 추천이 느리거나 실패해도 템플릿 화면은 그대로 동작한다.
- **REC-2** `구현됨` — 넣을 만한 후보가 없는 슬롯은 **비워 둔다.** 못 쓸 스냅으로 채우지
  않는다. 추천 점수는 슬롯 적합도이지 스냅 내용에 대한 주장이 아니며, 분석의 모델 출력
  (요약·주제 등)은 사용자에게 노출하지 않는다.
- **REC-3** `구현됨` — 추천은 **크레딧을 차감하지 않는다.** 비용은 상한으로 막는다:
  후보 1회 12개, 사용자당 최근 24시간 20회 (잠정값 — 단가 실측 후 재조정).
- **REC-4** `구현됨` — 추천(과 그것이 유발하는 분석)은 **분석에 동의한 사용자에게만** 돈다
  (ANA-5). 동의하지 않은 사용자는 로컬 매칭만 보고, 템플릿 화면은 그대로 동작한다(REC-1). 서버의 기능
  스위치(`MOVIE_RECOMMENDATION_ENABLED`)가 꺼져 있으면 동의와 무관하게 돌지 않는다. 약관·개인정보처리방침의
  법무 검토가 끝나기 전에도 이 동의를 근거로 켤 수 있다 — 2026-09-29 오너 결정, 근거는
  [decisions/snap-content-analysis.md](../decisions/snap-content-analysis.md) §6.1.

## 스냅 내용 분석

- **ANA-1** `구현됨` — 분석은 **명시적으로 요청될 때만** 돈다. 업로드했다고 자동 분석하지
  않는다 — 대부분의 스냅은 편집에 쓰이지 않으므로, 쓰일 후보가 정해진 시점에만 비용을 쓴다.
- **ANA-2** `구현됨` — 분석 결과(주제·장소·사물·행동·분위기·편집 사용 가능 여부)는 **자동
  편집·추천의 내부 입력**이며 사용자에게 보여주는 문구가 아니다.
- **ANA-3** `구현됨` — 외부 모델로 보내는 것은 **대표 프레임 최대 4장**뿐이다. 오디오는 보내지 않고, 영상이 삭제되면
  분석 결과도 함께 파기된다 — 사용자가 지우는 순간(최근 삭제에 들어가도) 지우고, 보관 기간이 끝나 정리될 때도 지운다.
  되살린 스냅은 분석이 필요해질 때 다시 분석한다. 이 전송 범위와 파기는 개인정보처리방침 문구와 테스트로 고정돼 있다.
- **ANA-4** `구현됨` — 같은 영상에 대한 분석 요청은 멱등하다(버전당 한 번). 분석 실패는
  원본 영상에 어떤 영향도 주지 않으며, 재시도 가능한 실패만 다시 돈다.
- **ANA-5** `구현됨` — 분석은 **사용자가 직접 동의해야** 돈다(옵트인, 기본은 동의 없음). 앱은 분석을
  쓰는 기능을 처음 쓸 때 무엇을(대표 장면 최대 4장, 소리는 보내지 않음) 어디로(외부 AI 사업자, 국외) 보내는지
  알리고 묻는다. 동의하지 않아도 그 기능은 분석 없이 동작한다. 동의는 **문구 버전과 시각**으로 기록되고,
  문구가 바뀌면 다시 묻는다. 사용자는 나 탭에서 언제든 동의를 끌 수 있고, 끄면 그 뒤로 분석하지 않으며
  이미 만든 분석 결과와 추천 기록을 파기한다. 동의는 서버가 집행한다 — 분석 요청과 추천 요청 모두 동의가
  없으면 거절된다.

## 사용자 취향 (개인화)

근거: [decisions/ontology-personalization.md](../decisions/ontology-personalization.md) (2026-10-13 결정). 남은 일은 [backlog.md](../backlog.md) A-13.

- **PRF-1** `구현됨`(2026-10-13 — 행동에서 배우는 것과 관심사) — 서버는 사용자마다 **취향**을 배운다. 취향은 스냅 내용과 같은 개념(장소 · 사물 · 행동 · 주제 · 분위기)과 편집
  선택(전환 · 스타일)에 대한 선호도이고, 사용자가 이미 하는 일에서만 배운다 — 고른 관심사(ACC-5), 추천 · 초안에 넘긴 스냅, 초안에서 남기거나
  지운 컷, 바꾼 전환 · 스타일, 끝까지 만든 무비. 끝까지 만든 무비가 가장 강한 근거다. 이것만을 위해 스냅을 따로 분석하지 않는다 —
  분석은 지금처럼 요청될 때만 돈다(ANA-1).
- **PRF-2** `구현됨`(2026-10-13 — 배우는 쪽과, 템플릿 순서 · 추천 · 전환에서 비선호를 빼지 않고 뒤로 미루는 반영) — 취향은 **한 번의 행동으로 뒤집히지 않고**, 같은 선택이 반복될 때 굳는다. 오래 쓰지 않은 취향은 서서히 옅어진다.
  싫어하는 쪽으로 기운 취향도 그 장면이나 전환을 **빼지 않고 뒤로 미룰 뿐**이다 — 사용자가 넘긴 스냅은 취향과 무관하게 초안에 쓸 수 있다.
- **PRF-3** `구현됨`(2026-10-13 — 템플릿 목록 순서 · 추천 슬롯 배정 · AI 가 고르는 전환 · AI 편집 초안(MOV-25 — 에이전트가 취향 상위 개념을 받고 분위기를 정한다) · 새 무비의 스타일 기본값. 템플릿 카드는 2026-10-15 부터 지금 스냅으로 다 채울 수 있는 것을 앞에 두고, 그 묶음과 나머지 묶음 안에서는 취향 순이다 — 몇 컷이 모자란지로는 순서를 바꾸지 않는다) — 취향은 템플릿 목록의 순서, 템플릿 추천의 슬롯 배정(REC-1), AI 편집 초안(MOV-25)에 반영된다.
  **새 무비의 스타일**은 앞서 정할 근거가 없을 때(자동 편집은 최근에 손댄 무비가 없을 때, 직접 고른 스냅의 새 무비는 늘) 취향이 권하는 스타일로 시작한다 —
  스타일 취향에 좋아하는 분위기가 어울리는 스타일을 더한 점수가 문턱(그 스타일로 무비를 한 편 완성한 정도)을 넘을 때만 권하고, 아니면 지금처럼 `일상`이다. 취향이 없는
  사용자(새 사용자 · 관심사 없음)도 모든 기능이 지금처럼 동작한다. **취향을 반영한 이유는 사용자에게 보이지 않는다**(ANA-2 와 같은 취급 —
  2026-10-13 보류 결정).
- **PRF-4** `구현됨`(2026-10-13 — 동의 철회 · 계정 삭제 · 관심사 해제 · 스냅 삭제의 취급) — 스냅 내용에서 배운 취향은 **분석 동의를 끄면 분석 결과 · 추천 기록과 함께 파기한다**(ANA-5). 관심사는 해제하면
  지우고, 계정을 지우면 취향 전부를 지운다(ACC-7). 스냅 하나를 지워도 그 스냅에서 배운 취향은 남는다 — 취향에는 스냅 내용이 남지 않는다.
